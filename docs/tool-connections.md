# Connect tools when the work requires them

Skills supply the QA method. The LLM host supplies actual capabilities. Begin with valid source analysis; connect only the tools needed for the selected task.

| Work | Required actual capability | What establishes readiness |
|---|---|---|
| Backlog/requirements | Supplied files or an authorized work-management connector | Selected scope and real source revisions |
| Browser verification | Compatible browser tools, such as an exposed Playwright MCP runtime | Actual tool inventory, permitted target, successful read-only connection and current page context |
| API checks | Authorized API client/request runtime and actual contracts | Target/build, account/data scope, oracle and evidence capture |
| Data investigation | Approved database access or sanitized extracts | Actual schema, bounded queries, snapshot and access limits |
| Continuous validation | Real repository/pipeline and scoped execution authority | Suites, runner, isolation, selected checks and artifact/gate behavior |

For Playwright MCP, procedure 34 verifies capability and procedure 20 executes the selected checks. A saved server entry or a terminal process is not proof that the current conversation has browser tools. Report actual startup/auth/launch errors. Keep runtime/session bindings current; do not fabricate navigation or screenshots.

Use each client's current MCP setup documentation. Configure secrets through supported mechanisms rather than prompts or repository files. An ordinary chat with a model does not automatically share a coding client's authenticated tools. Existing authorization applies within its actual scope; load/security/fault testing and deployments need their specific scope.
