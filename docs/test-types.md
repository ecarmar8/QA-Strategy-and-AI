# Test coverage by type

Use this catalog to decide applicability. A project does not need every row. Levels, functional concerns, quality attributes, change strategies and design techniques overlap; they are not interchangeable test types. Existing skills cover the analysis and execution workflow; tool access and product-specific expectations determine what can actually run.

## How the non-functional skill works

Skill 21 selects applicable attributes, confirms an objective and its source, defines workload/environment, checks scope and stop conditions, executes with compatible tools, and reports target versus actual with limitations. Skills 17 and 18 address integration and data behavior; 20 covers the browser; 25 integrates checks into CI; 28 uses the resulting evidence in a release decision.

For every applicable row record: risk → requirement/source → skill/owner → scenario and data → tool/environment → target and stop rule → measured actual → verdict/evidence → remaining gap. Missing targets are Pending definition; absent execution is Not Run. A local assertion does not verify a production service.

## Automation decisions

Use skill 15 to assess exposure, recurrence, determinism, oracle strength, data/environment control and maintenance burden. Prefer lower-layer controls where they give adequate evidence. Preserve exploratory, usability and specialist assessments where human judgment is the actual oracle. Use skill 28 to hold a release when essential protection fails or lacks required evidence; communicate consequence, affected scope, mitigation and next decision.
