# Apply the QA strategy

**For a visual overview:** open [index.html](index.html). Select Method, Skills, Problem solving, Metrics or LLM workflow.

**For project work:** read [QA_STRATEGY.md](QA_STRATEGY.md), [the shared contract](docs/operating-contract.md) and [procedure 00](docs/procedures/00-orchestrate-testing-lifecycle.md). Start with the actual product, people and delivery process, or resume a valid checkpoint. Use available sources before prescribing changes.

1. Understand the objective, users, critical workflows, architecture and current delivery.
2. Diagnose actual evidence, including escape mechanisms and waits where available.
3. Agree the scope, risks, controls and a focused improvement with the team.
4. Clarify early, design relevant coverage and verify on the actual build when ready.
5. Report current protection, remaining risk and the next decision. Review outcomes and adapt.

Use [the engagement plan](docs/engagement-plan.md), [working templates](docs/project-templates.md) and [problem-solving guide](docs/problem-solving.md). Select only the relevant [skills](docs/skills.md).

## Reusable starting instruction

```text
Apply MASTER_PROMPT.md and procedure 00 to this engagement.
Start from the product, people and actual delivery process.
Use supplied sources and current authorization; ask only for
missing information that changes the next decision.
Distinguish confirmed expectations, observations and proposals.
Produce the next useful artifact with source references,
unknowns, risk rationale and a concrete next action.
Use the process-risk metrics and keep artifacts in English.
```

For client discovery and tools, see [LLM clients](docs/llm-clients.md). Analysis does not require a browser connection; execution requires the actual tools, target and evidence.
