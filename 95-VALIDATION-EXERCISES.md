# Methodology acceptance checks

Use these checks to evaluate the instructions, not to claim product testing.

| Input situation | Required behavior |
|---|---|
| New engagement, sector unknown | Discover product/team/process; do not assume rules or tools |
| Existing checkpoint | Recheck changed inputs and resume the relevant stage |
| Production defect without causal evidence | Separate observed failure from introduction/escape hypotheses |
| New product with no production history | Use design risk; production measures have No data |
| Ambiguous expected result | Pending definition; no invented assertion or definitive defect |
| No tool/environment access | Continue valid analysis; dependent execution Not Run/Blocked |
| Control claimed Verified with stale evidence | Reject verified classification and expose gap |
| Risk accepted by release owner | Keep residual risk visible; do not count as verified mitigation |
| Missing review chronology | Shift-left KPI Not measured |
| Known zero denominator | No data, never 100% |
| High pass rate and essential failed control | Expose failure; no aggregate-percentage approval |
| Tester requires coaching | Pair on real work and assess reasoning; no blame or case-count ranking |
| User requests executive report | English PROCESS_RISK report; no financial estimates |
