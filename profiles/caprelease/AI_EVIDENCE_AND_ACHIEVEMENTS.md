## A CTO demonstration using real supplied material

Select one sanitized actual story, relevant acceptance criteria, dependency/contract and, if available, an escaped defect. Record source revisions. Use procedure 00, then 04/06/07/10/11 to produce a short reviewed question/risk/coverage chain. Show an AI suggestion you rejected or corrected and explain why. If actual schema/access exists, use 18 to investigate a concrete data assertion. If a safe target/runtime exists, execute only the agreed checks and retain evidence. End with the process-risk report and next decision.

Without those materials, show the authored method and explain the evidence needed; do not manufacture a company example, SQL schema, defect or passing run to make the presentation look complete. Generated text is not execution. A model's self-review is not independent validation.

## Measuring AI's contribution

Keep a ledger of source package, task scope, AI draft, accountable review, material corrections, final accepted artifact and actual effort. K14 evaluates first-review usefulness. K15 compares matched accepted work including review/rework. Keep model/tool and prompt/procedure versions where they affect reproducibility. Do not promise universal time reduction from a single successful task.
